# AGENTS.md

This file provides guidance to AI coding agents (Codex, Cursor, Copilot, …) working in this repository. It is the single source: `CLAUDE.md` only imports it (`@AGENTS.md`), so Claude Code reads the same text. Edit this file, not CLAUDE.md.

## Project

A personal website (hobby project, not client work). Content will mix: about-me/bio, a resume/CV page derived from the owner's actual CV and LinkedIn profile, a projects/portfolio section, links to socials, and eventually a blog.

Design goal: deliberately non-standard/non-templated. Avoid shipping a component library's out-of-the-box look (Aceternity/Motion Primitives/etc. read as "generic AI-hackathon site" when used wholesale) — favor a hand-picked color/type palette plus one or two restrained, deliberate interactions over stacking every available effect.

## Planned stack

- **Astro + Tailwind** — chosen for its plugin/theme ecosystem, near-zero shipped JS by default, and first-class free hosting (Vercel/Netlify/Cloudflare Pages).
- **CV/LinkedIn → content**: [JSON Resume](https://jsonresume.org) schema, populated via a LinkedIn-export converter (e.g. `linkedin-to-jsonresume`), rendered as a page and exportable to PDF.
- Reference starters worth borrowing structure/ideas from (not templates to clone wholesale): [astrofy](https://github.com/manuelernestog/astrofy), [astro-portfolio-starter](https://github.com/drehimself/astro-portfolio-starter).

### Setup / commands

- `npm run dev` — dev server at `http://localhost:4321`
- `npm run build` — static build to `dist/`
- `npm run preview` — serve the production build locally (daemonizes; `npx astro preview stop` to stop)
- `npx astro check` — type/diagnostics check
- `npm run qa` — build + standard browser QA pass (`qa/check.mjs`, see Process note)
- `node scripts/og-image.mjs` (after `npm run build`) — redraws the share preview `public/og.jpg` (1200x630 shot of the hero); rerun when the hero changes. Layout.astro carries the OG/Twitter tags, canonical and a schema.org `Person`; they need `SITE_URL` (set by the deploy) for absolute URLs.
- `node scripts/fonts.mjs` — downloads the self-hosted fonts into `src/assets/fonts/` and writes `src/styles/fonts.css` (incl. the metric-matched Georgia/Arial fallbacks); rerun when the claim's italic words change (the build tells you).
- **Deploy**: `.github/workflows/deploy.yml` (GitHub Actions → GitHub Pages) on every push to `master`; one-time setup: Settings → Pages → Source "GitHub Actions". It passes `SITE_URL`/`BASE_PATH` from `actions/configure-pages` to `astro.config.mjs`, so the site may live under `/<repo>/`: **every root-absolute path to a `public/` file or the page itself goes through `url()` from `src/lib/url.ts`** (`url("/img/…")`), never a bare `"/img/…"`. In-page anchors (`#werdegang`) and imported assets need nothing.

### Design rules (binding; the why is in docs/decisions.md)

- **Palette "Stahl + Sonnengelb"** (tokens in `src/styles/global.css`; `--ink` #0f1b2d, greys `--ink-2`/`--ink-3` keep 4.5:1 on every day colour, `--steel` never for text). **Sun yellow `--sun` means light and nothing else** (the hero sun, rays, receiver glow, the schematic's sun): nav, links, hovers, chips stay ink. Category colours `--c-edu` / `--c-thesis` / `--c-work` / `--c-ai` are fills, never text. `--ph` magenta only for placeholders.
- **Fixed light theme**, no `prefers-color-scheme: dark` (owner rejected white-on-dark).
- **The day while scrolling**: `data/day.ts` + `scripts/day.ts` set `--bg` per section with two light spots and grain behind everything (`.light`); a spot never sits opposite its background on the colour wheel. Frosted bars over it use `.frost` (global.css). The spectrum gradient is only on the nav's current-section bar and the Kontakt e-mail underline; don't spread it.
- **Type**: self-hosted fonts (`src/styles/fonts.css`, generated by `node scripts/fonts.mjs`; never `@fontsource`, never a Google Fonts link). Schibsted Grotesk for UI, Newsreader for headings and prose; `.display` (Newsreader 500) only for the section titles and the hero name; one heavy grotesk moment (the Kontakt e-mail). Newsreader italic is a subset of the claim's `*marked*` letters: the build fails if the claim needs a new letter, then rerun the script. `.tnum` only on digit-only strings.
- **Every change must work on every screen**: phones 320-480, tablets (portrait too), short laptop windows (1024x560 to 1536x730) and large displays to 2560. Size by window with the fluid clamp tokens (`--gutter`, `--sp-section`, `--sp-block`, `--sp-gap`, `--col-meta`, `--col-side`); adapt before falling back, never silently on common laptop sizes. Check reduced motion too: global.css sets `transition-duration: 0s` then (never back to 0.01ms: scripts measuring after a change read the old value).
- **Paths**: every root-absolute path to a `public/` file goes through `url()` from `src/lib/url.ts` (the site may live under `/<repo>/`); in-page anchors and imported assets need nothing.
- **CSS cascade**: media-query overrides come *after* the base rule they override (this broke the site twice); page-level overrides of layout/global rules need higher specificity (`:global(:root)`, `:global(main.content#inhalt)`) because Astro's scoped selectors carry an extra attribute.
- **Structure lines**: the top bar and section breaks (`.sec`) are one 1.5px ink rule; hairlines inside. Hover-to-trace uses an ink outline, never sun.
- **Hobbys shelf (three.js)**: keep the shader-program count low (every `phys()` material carries the same features; no `transmission`, no `sheen`), one shared lamp light, shadow map redrawn only when objects move; a software renderer steps aside to the list (`?force3d` overrides it, qa uses it).
- **Avoid the generated-site tells**: no uppercase tracked eyebrows, no mono micro-labels, no KPI stat tiles (incl. "big word + small caption"), no "→" appended to links, no middle-dot meta strings, sparing em dashes, no numbered "how it works" steps, no repeated meta-line → bold title → paragraph → link recipe, no boxed-card grids. Copy: plain, specific German; no aphorisms or filler; never invent facts, figures or skill levels (levels only where the CV rates them).
- **Generated pictures** carry a small "Generiert mit KI" tag (owner's rule). AI-drafted text is no longer marked (owner 2026-10-09); `Placeholder.astro` stays unused.
- The home `<meta name="description">` stays neutral and factual, never the AI claim.

### Process note

When asked for a substantial redesign, the owner wants a build → test → fix loop with the testing step done by a **separate subagent** (Agent tool, fresh `general-purpose`, not a `fork`) that only reports bugs — it doesn't edit files. Reviews should include real screenshots. Design critique goes to a *separate* fresh agent told to be blunt, not the bug tester.

**When to test** (owner 2026-10-09: "do not run a check every time", but changes must not pile up untested). Sort each change:
- **Small**: wording or data in `cv.ts` (a line rephrased, a sub-point added or removed), a typo, a comment. No tester, no `npm run qa`. Exception: if it makes a Kernkompetenzen card noticeably longer (a new main point, several new lines), run `npm run qa` once (30 s, automated), because the pile may stop fitting short laptop windows.
- **Larger**: anything in CSS, scripts or markup structure, a new section or component, a layout change, several files at once. `npm run qa`, then a fresh tester subagent, then fix and do a narrow re-check.
- **Piling up**: keep count of the small changes since the last tester run. A tester runs over everything untested when (a) 3 or more small changes have collected, (b) a larger change comes on top of untested small ones, or (c) before a commit or push that contains untested work. The tester gets the diff since the last tested state, not just the last edit.

**The tester only checks the current changes** (owner 2026-10-09): its prompt names the files and what changed, and it starts from `git diff` (uncommitted work, or the commit range under test). It tests what the diff touches and what the diff can break (same component, same layout at all sizes), not the whole site, and it does not report old issues outside the diff (it may list them in one line at the end as "seen, outside the change").

**Keep test rounds fast** (2026-10-02: agent rounds took 25–66 min, mostly from 40–80 tool calls of one-off scripts, broad prompts, fixed sleeps and screenshot reading):
- **Fixed 2026-10-10**: (1) "Werdegang: the text jumped Nx" in `npm run qa` at 1440x900 was the reduced-motion rule (see above), not Werdegang. (2) A fresh visit to `/#section` below Werdegang (Kenntnisse, a certificate, Hobbys, Kontakt) landed hundreds of px off because the browser jumps before the hero, the pile and Werdegang settle their heights; a small script at the end of index.astro lands again after load (Kernkompetenzen sheets and Werdegang stations land themselves). `npm run qa` sets the hash after load, so it can't catch (2): test fresh `/#id` loads by hand or in a script.
- **`npm run qa`** (`qa/check.mjs`, Playwright 1.63 is a dev dependency) is the standard pass: it builds, serves the build (not the dev server: faster, no stale CSS), and checks per size console/page errors, horizontal overflow (naming the culprits), dead or removed-page links, the heading outline, where anchors land (sections and cards under the top bar, stations under the pinned chart) card titles below the bar where they pin,  About 30 s for four sizes. `astro preview` runs as a background service (a second start only says "already running", killing the launcher doesn't stop it), so the script runs `astro preview stop` before and after; test scripts that start a preview must do the same. `--sizes 320x640,390,768,1440`, `--shots` (one screenshot per section and size into `qa/shots/`, gitignored), `--base <url>` for a running server. Run it after every change and before a commit; when a tester finds a bug the harness could catch, add the check to it.
- Tester prompts: start from `npm run qa`, then only the **targeted** checks the change calls for. Default sizes 390 / 768 / 1366x657 / 1440 (+ 320 when phones are affected, + 1024x560 / 1280x600 / 1536x730 when heights matter). **Re-checks are narrow**: just the bugs that were fixed plus `npm run qa`; a full sweep only after big changes. A faster model (`model: "sonnet"`) is fine for re-checks; the first test of a big change stays on the strong model.
- In test scripts: wait for conditions (load, `document.fonts.ready`, two animation frames), not fixed sleeps; a hard time limit per script (60 s); numbers first, screenshots only for checks that are really visual; reuse `qa/check.mjs` helpers instead of writing scripts from scratch.
- Old one-off scripts and screenshots from earlier rounds are in an earlier session scratchpad (`%TEMP%/claude/C--Users-danie-personal-website/740c1ef4-b3ce-4d89-b99b-045aa187fe5c/scratchpad/browser`); they are not needed any more. WebKit/Firefox are not installed (`npx playwright install webkit` if a Safari check matters).
