# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A personal website (hobby project, not client work). Content will mix: about-me/bio, a resume/CV page derived from the owner's actual CV and LinkedIn profile, a projects/portfolio section, links to socials, and eventually a blog.

Design goal: deliberately non-standard/non-templated. Avoid shipping a component library's out-of-the-box look (Aceternity/Motion Primitives/etc. read as "generic AI-hackathon site" when used wholesale) — favor a hand-picked color/type palette plus one or two restrained, deliberate interactions over stacking every available effect.

## Planned stack

- **Astro + Tailwind** — chosen for its plugin/theme ecosystem, near-zero shipped JS by default, and first-class free hosting (Vercel/Netlify/Cloudflare Pages).
- **CV/LinkedIn → content**: [JSON Resume](https://jsonresume.org) schema, populated via a LinkedIn-export converter (e.g. `linkedin-to-jsonresume`), rendered as a page and exportable to PDF.
- Reference starters worth borrowing structure/ideas from (not templates to clone wholesale): [astrofy](https://github.com/manuelernestog/astrofy), [astro-portfolio-starter](https://github.com/drehimself/astro-portfolio-starter).

### Design concept (v4)

- **Palette "Stahl + Sonnengelb"** (tokens in `src/styles/global.css`): steel paper `--bg` #f4f6f8 (page and top bar), white `--paper` for raised surfaces (skill boxes, figure panels), ink `--ink` #0f1b2d, `--ink-2` #4f5d6e secondary text, `--steel` #7d8b99 for mirrors/ghost lines (never text), `--line` hairlines, `--ink-3` #64707d stepped-back text (4.66:1), `--wash` #e7ebf0 quiet bands, `--steel-soft` #dde3ea neutral fill (selection, AM lead area), **sun `--sun` #f2a900**. Sun yellow means **light, and nothing else**: the hero's sun, rays and receiver glow, the AM break-even dot, the heliostat schematic's sun. Nav, links, hovers, chips stay ink (a blunt critic caught yellow spreading to nine uses, the v2 "one accent everywhere" failure; keep it scarce). Fill only, always with ink text or an ink outline on it. `--ph` magenta stays outside the palette for placeholders.
- **Fixed light theme only**, deliberately **no** `prefers-color-scheme: dark` override (owner rejected white-on-dark).
- **Type**: one Google Fonts `<link>` (avoid `@fontsource`: subpath-export bug, likely the space in `personal website`). **Schibsted Grotesk** for UI. **One heading voice** (2026-10-01): `.display` = **Newsreader 500**, tracking -0.02em, for the five section titles (Kernkompetenzen, Werdegang, Kenntnisse, Kontakt; all the same `.page-title`) and, set inline, the hero name. **One heavy grotesk moment**: the Kontakt e-mail (Schibsted 800; a critic found serif-only reading as the stock editorial portfolio) (owner: the heavy grotesk looked clunky; picked from mockups in `.superpowers/brainstorm/hero-name-fonts.html`; a critic then found the page switching voice between the serif top and grotesk sections). The top bar name is Newsreader 600. Section heads (Software, Zertifikate, Neben dem Job) = Schibsted 700 ~1.25rem, quiet. **Newsreader** 600 for content headings (station titles, essay and practice titles, skill box titles) and `.text` for prose, claim, stories. (The critic found every heading in heavy grotesk again, so hierarchy collapsed to size alone; don't spread `.display`.) Careful: Schibsted's `tabular-nums` (`.tnum`) also widens `,` and `.` to digit width ("1 . 566"), so use `.tnum` only on digit-only strings (years, slider outputs), never on prose with decimals.
- **Fluid sizing** (owner 2026-10-02: "flexible heights and pixels, not fixed ones"): layout sizes come from clamp tokens in global.css that grow with the window width between a phone floor and a desktop cap: `--gutter`, `--sp-section` (above a section title), `--sp-block` (below sections, between big blocks and stations), `--sp-gap` (between columns), `--col-meta` / `--col-side` / `--col-title` (Werdegang columns; `--col-meta` is also the chart's lane-label column), `--col-index` (Kernkompetenzen index). Field heights scale by width too (hero strip on phones, page-end field). Above 1440px the root font size grows too (`html { font-size: clamp(100%, 0.64rem + 0.4vw, 118.75%) }`: 16px at 1440, ~19px at 2560; below it stays the browser default and follows the visitor's setting), so every rem size scales with large displays, and the content column `--wrap` is `min(max(72rem, 62vw), 100rem)` (it was a fixed 72rem: half of a 2560 screen was margin). Body text is 1.0625rem, not px. Use the tokens for new layout sizes instead of fixed rem values; small UI sizes (icons, logos, borders, the top bar) stay fixed on purpose. `npm run qa` checks 320–2560.
- **Structure lines**: the top bar and the section breaks (`.sec` in global.css: Werdegang, Kenntnisse, Kontakt; the hero is closed by the field's ground line) are one 1.5px ink rule; hairlines inside.
- **Hover-to-trace** (owner liked it): pointing at something picks it out together with what it links to, with an **ink** outline/bar (not sun): Werdegang chart bar ↔ station (the skill-name → rows trace went with the per-station skill lines). Links hover to a thicker ink underline.

### Architecture

- `src/data/cv.ts` — all CV/LinkedIn/thesis content as typed data: `profile` (incl. `claim`), `career` (each with `story`; `from`/`to` as `"2020"`, `"Okt 2021"` or `"heute"`; optional `minor` and `project` slug), `projects` (ordered by weight; `slug` = anchor, optional `figure`), `ratedSkills`, `competencies`, `otherCompetencies`, `certifications` (with `id` anchors), `notes`, `topSkills` (home hub, Kenntnisse grouping, Werdegang chips: `id`, `title`, `proof[]`, `tools[]`, optional `toolsQuestion`, `learned[]`). `career[].id` and `certifications[].id` are link targets, keep them stable. Edit content here, not in components. Exceptions: the AM model's essay text lives in `AmModel.astro`, the life-cycle numbers in `LifeCycle.astro` (both written around their figure).
- `src/data/nav.ts` — the in-page anchors for the top bar and the CV PDF path. `src/data/tools.ts` — software logos.
- `src/lib/dates.ts` — `toFrac()` turns `from`/`to` strings into fractional years (year-only starts count as September, ends as July; "heute" = build date, so rebuild to move it).
- `src/lib/heliostat.ts` — hero field geometry (`FIELD`, `MIRROR_X`, `SUN_START`, `poses()`, `clampSun()`, `fieldEfficiency()`), shared by server render and client script.
- `src/lib/amModel.ts` — AM model constants, presets, `amModel()`, `amMarks()`, `amSvg()`, `amVerdict()`, formatters.
- `src/components/` — `Placeholder`, `ImagePlaceholder`, `sections/Werdegang`, `sections/Kenntnisse`, `sections/Kontakt`, `figures/HeliostatField`, `figures/Heliostat` (reflection schematic, in the Bachelorarbeit station), `figures/LifeCycle` and `figures/AmModel` (unused while Projekte is out).
- `src/layouts/Layout.astro` — shell: fonts, `html.js` one-liner, skip link, draft notice, top bar with the section scroll spy, `<main id="inhalt" class="content">`. Sections wrap their own content in `.wrap` so bands can go full-bleed.
- `src/pages/index.astro` — the only page: hero, Kernkompetenzen, then the three section components.

### Process note

When asked for a substantial redesign, the owner wants a build → test → fix loop with the testing step done by a **separate subagent** (Agent tool, fresh `general-purpose`, not a `fork`) that only reports bugs — it doesn't edit files. Reviews should include real screenshots. Design critique goes to a *separate* fresh agent told to be blunt, not the bug tester.

**Keep test rounds fast** (2026-10-02: agent rounds took 25–66 min, mostly from 40–80 tool calls of one-off scripts, broad prompts, fixed sleeps and screenshot reading):
- **`npm run qa`** (`qa/check.mjs`, Playwright 1.63 is a dev dependency) is the standard pass: it builds, serves the build (not the dev server: faster, no stale CSS), and checks per size console/page errors, horizontal overflow (naming the culprits), dead or removed-page links, the heading outline, where anchors land (sections and cards under the top bar, stations under the pinned chart) card titles below the bar where they pin, and the page-end sun inside the picture and clear of the mirrors. About 30 s for four sizes. `astro preview` runs as a background service (a second start only says "already running", killing the launcher doesn't stop it), so the script runs `astro preview stop` before and after; test scripts that start a preview must do the same. `--sizes 320x640,390,768,1440`, `--shots` (one screenshot per section and size into `qa/shots/`, gitignored), `--base <url>` for a running server. Run it after every change and before a commit; when a tester finds a bug the harness could catch, add the check to it.
- Tester prompts: start from `npm run qa`, then only the **targeted** checks the change calls for. Default sizes 390 / 768 / 1440 (+ 320 when phones are affected). **Re-checks are narrow**: just the bugs that were fixed plus `npm run qa`; a full sweep only after big changes. A faster model (`model: "sonnet"`) is fine for re-checks; the first test of a big change stays on the strong model.
- In test scripts: wait for conditions (load, `document.fonts.ready`, two animation frames), not fixed sleeps; a hard time limit per script (60 s); numbers first, screenshots only for checks that are really visual; reuse `qa/check.mjs` helpers instead of writing scripts from scratch.
- Old one-off scripts and screenshots from earlier rounds are in an earlier session scratchpad (`%TEMP%/claude/C--Users-danie-personal-website/740c1ef4-b3ce-4d89-b99b-045aa187fe5c/scratchpad/browser`); they are not needed any more.
